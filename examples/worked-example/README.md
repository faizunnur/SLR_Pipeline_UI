# Worked example: federated learning for intrusion detection

This folder holds the complete output of the worked example described in the
slr-pipeline software paper: a small systematic review run end to end with the
pipeline, small enough for any reader to repeat in minutes.

**Review question.** How is federated learning applied to intrusion detection
in networked and IoT environments?

**Protocol.** Query "federated learning intrusion detection", publication
years 2023-2025, sources OpenAlex, Crossref and Semantic Scholar (all usable
without an API key), capped at 30 records per source for demonstration scale.
Eligibility criteria, fixed before screening: include primary and secondary
studies that apply or study federated learning for intrusion or anomaly
detection within the date window; exclude records outside the window and
records that are not research articles.

**Results.** 60 records retrieved (Semantic Scholar returned none: its
anonymous pool refused the request with HTTP 429, and the failure is recorded
in the search-strategy log), 3 duplicates removed, 57 records screened,
49 passing the title-and-abstract gate and 8 excluded with reasons recorded.
A verification pass over 14 references - 12 genuine and 2 deliberately planted
errors - passed the genuine references and failed both planted errors.

## Files

- `candidates.csv` - the 60 retrieved records, one row per record.
- `candidates_search_strategy.csv` - the exact query sent to each source,
  with timestamps, totals available and truncation flags (PRISMA items 6-7).
- `candidates_dedup.csv` - all 60 records with deduplication decisions:
  removed records name the record they duplicate and the matching method.
- `screening.csv` - the 57 unique records with the reviewer's
  title-and-abstract decision and reason for every record.
- `references.bib`, `references.ris` - the 49 studies that passed screening,
  exported for a reference manager.
- `references.csv` - the 14 references submitted to citation verification
  (12 genuine, plus the 2 planted errors: labels plant-a and plant-b).
- `verification.csv` - the verification result for every reference: status,
  the Crossref record it resolved to, and the title-match score.
- `prisma_2020.png` - the PRISMA 2020 flow diagram generated by the
  pipeline's own figures stage from these files.

## Repeating the run

From the repository root, with the package installed:

```bash
python src/scripts/search.py --query "federated learning intrusion detection" \
    --year-from 2023 --year-to 2025 --mailto you@example.com \
    --sources openalex,crossref,semanticscholar --max-per-source 30 \
    --out output/candidates.csv
python src/scripts/dedup.py --in output/candidates.csv \
    --out output/candidates_dedup.csv --title-threshold 92
python src/scripts/screen.py --in output/candidates_dedup.csv \
    --out output/screening.csv
# fill in ta_decision and ta_reason in screening.csv, then:
python src/scripts/export.py --in output/screening.csv --included-only
python src/scripts/verify_citations.py --csv output/references.csv \
    --out output/verification.csv
python src/scripts/figures.py --screening output/screening.csv \
    --dedup output/candidates_dedup.csv --candidates output/candidates.csv \
    --outdir figures
```

Live sources change over time, so a repetition retrieves a similar but not
identical set of records; the stage outputs and decision trails are produced
the same way.
